# 5. Алгоритмы и модель ученика

## 5.1. Модель ученика (Learner Model)

Единое хранилище «что ученик знает», которое читают и пишут все модули.

| Объект знания | Модель | Что хранится |
|---------------|--------|--------------|
| **Слово** (лексема + значение) | FSRS | D, S, R, история повторений, направление (рецептивно / продуктивно) |
| **Грамматическая единица** | FSRS + оценка освоения (BKT/Elo) | P(освоено), стабильность, типичные ошибки |
| **Корень Ханча** | FSRS | Как у слова + связи в графе |
| **Звук / фонемный контраст** | Elo по парам | Точность различения ㄱ/ㅋ/ㄲ и т.д. |
| **Навык** (4 шт.) | IRT (θ по шкале 급) | Оценка способности ± ошибка, обновляется после каждого задания |
| **Ошибка** | Запись 오답노트 | Тип, контекст, статус (открыта / 1/3 / 2/3 / закрыта) |

**Важно:** знание слова различается **рецептивно** (узнаю) и **продуктивно** (могу сам вспомнить и написать). Покрытие текста считается по рецептивному, активный словарь — по продуктивному.

## 5.2. FSRS: интервальное повторение

Модель памяти DSR:
- **R (retrievability)** — вероятность вспомнить сейчас: `R(t) = (1 + F · t / S)^C` (степенная кривая забывания; F, C — константы версии FSRS).
- **S (stability)** — через сколько дней R упадёт до 90%.
- **D (difficulty)** — 1…10, насколько трудно для этого ученика.

**Цикл:**
1. Ответ ученика → оценка: `Again / Hard / Good / Easy`. В тестовых карточках оценка выставляется **автоматически** по правильности и времени ответа (ученик не должен сам себя оценивать в упражнениях).
2. FSRS обновляет D и S, назначает следующий интервал так, чтобы R в момент повторения = **целевому удержанию** (по умолчанию 0,90, настраивается 0,80–0,95).
3. После ~1000 повторений — **оптимизация 19–21 параметров** под конкретного ученика (на сервере, раз в неделю).

**Расширения под наш продукт:**
- **Связанные карточки** (sibling burying): КР→РУ и РУ→КР одного слова не показываются в один день.
- **Неявные повторения**: если ученик встретил слово в книге и **не** нажал на него — это слабый сигнал «узнал» (обновляем с пониженным весом). Если нажал — сигнал «забыл».
- **Грамматика в FSRS**: «карточка» грамматики — это не одно предложение, а **генератор** заданий: каждый раз новое предложение (из банка или сгенерированное и проверенное), чтобы не запоминался конкретный ответ.
- **Контроль нагрузки**: прогноз числа повторений на 30 дней вперёд → максимальное число новых карточек в день вычисляется так, чтобы повторения уложились в выбранное ученик время дня.

## 5.3. Подбор текстов i+1 (покрытие лексики)

Для каждого текста библиотеки заранее хранится список лемм (после морфологического разбора).

```
coverage(text, learner) = Σ freq(w in text) · known(w) / Σ freq(w in text)
known(w) = 1, если R_receptive(w) ≥ 0.8 или слово — имя собственное / число
         = 0.5, если слово сино-корейское и все его корни ханча известны (догадка)
         = 0,   иначе
```

| Режим | Целевое покрытие | Ещё условия |
|-------|------------------|-------------|
| Экстенсивное чтение | ≥ 97% | Все грамматические единицы текста освоены (P ≥ 0.7) |
| Интенсивное (урок) | 90–95% | Не более 2 новых грамматических единиц |
| «Вызов» | 85–90% | Только по желанию, с полными глоссами |

**Ранжирование** подходящих текстов: покрытие → интерес (жанр, клубы ученика) → «полезность» (сколько новых слов из списка текущего 급 и слов на грани забывания содержит текст: чтение работает как повторение).

## 5.4. Вступительный и диагностический тесты (CAT/IRT)

- Банк заданий откалиброван по модели **2PL IRT** (сложность b, дискриминация a) на данных пилотных пользователей; стартовая калибровка — экспертная, по уровням NIKL / TOPIK.
- Алгоритм: стартуем с θ = 2.0 (2급) → выбираем задание с **максимальной информацией** при текущем θ → обновляем θ (EAP) → стоп, когда стандартная ошибка < 0.3 или 25 заданий.
- Отдельный θ для каждого навыка; задания по навыкам чередуются.
- Тот же движок оценивает навыки **непрерывно** по обычным упражнениям → «Прогноз TOPIK» в зачётке.

## 5.5. Генератор учебного дня (시간표)

Вход: доступное время T, юнит и урок по программе, очередь FSRS, открытые записи 오답노트, ближайший экзамен, баланс навыков за последние 7 дней.

```
1. 조회     = обязательные повторения FSRS (R ниже цели), но ≤ 30% T.
              Если долг больше — приоритет по (1−R) × важность слова для текущего 급.
2. 1교시    = следующий урок программы (если урок уже пройден — следующий; если тест юнита провален — 보충수업).
3. 2교시    = текст/аудио урока ИЛИ подходящий текст из библиотеки (i+1).
4. 3교시    = вывод: перевод РУ→КР / диалог / письмо по материалу дня.
5. 종례     = 3–5 открытых записей 오답노트 (интерливинг разных типов).
6. Балансировка: если какой-то поток Nation за 7 дней < 15% — блок 2/3/쉬는 시간 смещается в его сторону.
   Если до экзамена < 7 дней — режим «подготовка»: пробные секции TOPIK.
7. Сложность заданий подстраивается так, чтобы ожидаемая точность ≈ 85%.
```

Ученик видит итог как **расписание с уроками** и может переставить или пропустить блок (автономия), но алгоритм напомнит, что выпало.

## 5.6. Проверка свободных ответов

Конвейер для перевода, письма и диалога:

1. **Нормализация**: пробелы, унификация 띄어쓰기 (если не проверяем именно её), регистр.
2. **Точное совпадение** с одним из эталонов → верно.
3. **Морфологическое сравнение**: разбор ответа и эталонов, сравнение лемм и цепочек окончаний — ловит «правильно, но другой порядок / опущено подлежащее».
4. **Правила**: детекторы типичных ошибок (частица, нерегулярность, -아서 + повелительное, регистр vs заданный собеседник).
5. **LLM-оценщик** (с 3급 или когда шаги 2–4 не дали ответа): эталон + ответ + контекст + рубрика → JSON `{verdict, errors[{span, type, fix, rule_id}], naturalness, register}`.
6. **Калибровка**: выборочная проверка преподавателями-носителями, метрика согласия с людьми (цель: κ ≥ 0.75). Ответы с низкой уверенностью помечаются как «спорный — отправить на проверку».

## 5.7. Аналитика и обратная связь

- **Кривая забывания ученика**, прогноз «сколько слов вы будете знать через 3 месяца при текущем темпе».
- **Тепловая карта ошибок** по типам.
- **A/B-эксперименты** на уровне платформы: порог мастерства (75/80/85%), целевое удержание FSRS, доля вывода. Метрика — не время в приложении, а **прирост θ за 30 дней** и сдача экзаменов.
